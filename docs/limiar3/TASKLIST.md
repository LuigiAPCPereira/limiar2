## Restrições transversais

- Cada tarefa concreta é decomposta em fatias médias completas no momento de implementação; IDs filhos e ADRs são criados só quando existe motivo, sem duplicar tracker.
- Em L3-001 não tratar decisões 021–024 Proposed como Accepted, nem histórico de teste/CI como validação do Limiar 3.0.
- Se o Engineering DNA original da Project não estiver integralmente presente e verificado no GitHub, **L3-DOC-001 não está validada**. Guia condensado `ENGINEERING_GUIDE.md` é útil mas não é entrega integral.
- Não há autorização atual de PR, merge, deploy, credenciais, conexão Telegram/MCP, código ou descarte de dados. Uma autorização futura pode liberar L3-002 depois da investigação e das decisões necessárias.
- Progresso é por critério e Evidence, não percentual arbitrário. A última revisão validada e a próxima ação apontando para ID são registradas no checkpoint.
